# Chapter 4: Functions

## 4.1 Functions

- Adjacent parameters of the same type can share one type: `func concat(s1, s2 string) string`. Every parameter still needs a type. `func f(x, y) int` does not mean "infer the type": the parser reads it as two unnamed parameters of types `x` and `y`. Measured: the compiler reports `undefined: x` and `undefined: y`, not a missing-type error.
- Function order in a file does not matter, and neither does order across files in a package. Package-level declarations are resolved before any body is checked.
- `s1 + s2` allocates a new string, because strings are immutable. One expression with several operands is still one allocation. Measured with `testing.AllocsPerRun`: `a + b + c + d` makes 1 allocation. `s += a` in a loop of 100 makes 99, and the copying is quadratic in the final length. A `strings.Builder` with `Grow` makes 1. Build log lines or payloads in a loop, for example joining decoded CAN frame fields, with `strings.Builder`, `strings.Join`, or `fmt.Fprintf` to a writer.
