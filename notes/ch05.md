# Chapter 5: Structs

## 5.1 Structs in Go

- A struct's zero value has every field set to its zero value, so `var m messageToSend` is ready to use. Measured: `%v` prints `{0 }`, `%+v` prints `{phoneNumber:0 message:}`, and `%#v` prints `main.messageToSend{phoneNumber:0, message:""}`. Use `%+v` in log lines so that an empty string field stays visible.
- A struct whose fields are all comparable is comparable with `==`. Measured: two `messageToSend{1, "x"}` values compare equal. Such a struct can also be a map key.
- Size is the sum of the fields plus alignment padding. Measured on amd64: `messageToSend` is 24 bytes (8 for `int`, 16 for the string header). The lesson's `car` is 48 bytes. Field order affects padding when small and large fields are mixed.
- `int` is 32 bits on 32-bit targets. The course's test cases use `148255510981`, which needs more than 32 bits. Measured: `GOARCH=arm GOARM=7 go vet ./ch05/l01` fails with `cannot use 148255510981 (untyped int constant) as int value in struct literal (overflows)`. On an ARMv7 gateway, use `int64` for any value that can pass 2^31.
- In production, a phone number is a `string`, usually in E.164 form (`+30697...`). An integer drops the `+` and any leading zero, and it allows arithmetic that has no meaning. A literal with a leading zero is octal in Go. Measured: `0030697123456` fails with `invalid digit '9' in octal literal`.

## 5.2 Nested Structs in Go

- A nested struct field is a value, not a pointer. Its zero value is a usable `user{}`, so `m.sender.name = "a"` on a zero `messageToSend` needs no allocation and cannot panic. Measured: `messageToSend` is 64 bytes on amd64 (16 for the string header and 24 for each `user`), and the whole value is copied when passed to `canSendMessage`.
- The solution uses a local closure, `isValidUser`, so the check is written once for sender and recipient. It costs nothing. Measured with `go test -gcflags=-m`: `can inline canSendMessage.func1`, `inlining call to canSendMessage.func1` at both call sites, and `mToSend does not escape`. Compare 4.16, where a closure that escaped moved its variable to the heap. The usual home for this check is a method, `func (u user) valid() bool`, which a later lesson introduces.
- `u != user{}` is not the same check. It is true when any field is set, and the spec needs every field set. Measured: `user{name: "x"} != user{}` is `true`, but that user has no number.
- In production, validation returns an `error` that names the missing field, not a `bool`. The caller can then log or reject with a reason, for example `errors.Join` of `recipient: missing number` and `sender: missing name`. A `bool` says only that something is wrong. The same applies to rejecting an IoT message with a missing device ID or topic.

## 5.3 Anonymous Structs in Go

Quiz:

1. What is a good reason to use an anonymous struct? It is only being used once. Privacy, security and speed are wrong answers.
2. What's one advantage of using an anonymous struct? It prevents you from reusing a struct definition you never intended to reuse. It does not make code run faster or compile more quickly.

Notes:

- A name does not change a struct's layout, so an anonymous struct has no run-time cost or gain. Two struct types with the same field names, types, order and tags are identical. `%T` prints the type literal: `struct { X int; Y int }`.
- A value of an anonymous struct type is assignable to a named type with the same underlying type, because one side is unnamed. Measured: `var p point = struct{ X, Y int }{1, 2}` compiles, and a `point` can be passed to `func(p struct{ X, Y int })`.
- Tags are part of type identity for assignment but not for conversion. Measured: assigning a struct with `json:"x"` tags to `struct{ X, Y int }` fails with `cannot use b (variable of type struct{X int "json:\"x\""; Y int "json:\"y\""}) as struct{X int; Y int} value in variable declaration`. The explicit conversion `struct{ X, Y int }(b)` compiles (allowed since Go 1.8).
- Common production uses: the table in a table-driven test (`tests := []struct{ name string; in, want int }{...}`), and decoding one JSON response in one function. Measured: ``var resp struct{ Data struct{ ID string `json:"id"` } `json:"data"` }`` decoded `{"data":{"id":"dev-1","extra":1}}` to `{Data:{ID:dev-1}}`. The unused field was ignored. Once a second function needs the shape, give it a name.

## 5.4 Embedded Structs

- Embedding `user` in `sender` promotes `name` and `number`, so `s.name` works and means `s.user.name`. The field's name is the type name, `user`. Embedding is composition, not inheritance: a `sender` is not a `user`, and a function that takes a `user` needs `s.user`.
- The lesson says promoted fields must be set through the embedded struct in a composite literal. That changed in Go 1.27. Measured with this module's toolchain: `sender{name: "Deb", number: 1, rateLimit: 10}` compiles and prints `{user:{name:Deb number:1} rateLimit:10}`. With `-lang=go1.26` it fails with `use of promoted field user.name in struct literal of type sender requires go1.27 or later (-lang was set to go1.26; check go.mod)`. As with the loop variable in 4.16, the `go` line in `go.mod` decides. The course's test uses the older `user: user{...}` form, which still works.
- Methods are promoted too, and that can surprise you. Measured: when `user` has a `String() string` method, `fmt.Println(s)` and `fmt.Printf("%+v", s)` on a `sender` both print `user:Deb`. The `rateLimit` field disappears from the output, because `sender` now satisfies `fmt.Stringer` through `user`. The same applies to a promoted `MarshalJSON` or `Error` method.
- `encoding/json` flattens an embedded struct into the outer object. Measured: an embedded `user` with exported fields marshals to `{"Name":"Deb","Number":1,"RateLimit":10}`. A named field `User user` gives `{"User":{"Name":"Deb","Number":1},"RateLimit":10}`. Choose on purpose: changing between the two forms changes the wire format, for example an IoT payload schema.

## 5.5 Struct Methods in Go

- A method is a function with a receiver. `a.getBasicAuth()` is shorthand for `authenticationInfo.getBasicAuth(a)`, the method expression form. A value receiver gets a copy of the struct, so the method cannot change the caller's value. Pointer receivers come later.
- The receiver name is short and the same on every method of the type (CodeReviewComments, "Receiver Names"). Here that is `a`. Never use `this` or `self`.
- The course's string is not real HTTP Basic auth. RFC 7617 base64-encodes `user:password`, and the header name is not part of the value. Measured: `req.SetBasicAuth("Google", "12345")` sets `Authorization` to `Basic R29vZ2xlOjEyMzQ1`, and `req.BasicAuth()` decodes it back to `Google 12345 true`. In production, call `SetBasicAuth` and do not build the header by hand. Basic auth is only an encoding, so it needs TLS.
- A struct that holds a password leaks it to any formatted log line. Measured: `%+v` prints `{username:Google password:12345}`. Implement `slog.LogValuer` to redact it. Measured: `LogValue` returning a group with `password` set to `REDACTED` logged `auth.username=Google auth.password=REDACTED`. This is the same risk as logging a device's AWS IoT credentials or a private key path with `%+v`.

## 5.6 Memory Layout

- Each field is aligned to its own size, up to the word size, and the struct's size is rounded up to a multiple of its largest alignment. Ordering fields from largest to smallest removes the padding between them. Measured on amd64: `contact` is 24 bytes (16 + 4 + 4) and `perms` is 16 bytes (8 + 3 bools + 5 bytes of tail padding). Badly ordered versions are 32 bytes (`int32`, `string`, `int32`) and 24 bytes (`bool`, `int`, `bool`, `bool`).
- Padding is paid once per value, so it matters only when there are many values. Measured: one million `perms` in a slice take 16,000,000 bytes, and one million of the bad order take 24,000,000. This is relevant for a ring buffer of decoded CAN frames on a memory-limited gateway. For a single config struct, order fields for readability.
- Sizes depend on the architecture. Measured with `GOARCH=386`: `contact` is 16 bytes and `perms` is 8, because `string` is 8 bytes and `int` is 4. The bad orders are 16 and 12. The course's test expects the amd64 values, so it fails on a 32-bit ARM gateway.
- `fieldalignment` finds these structs. It is part of `govet` in golangci-lint, but off by default. Measured with `govet: enable: [fieldalignment]`: `permsBad has size 24 but the optimal size is 16 leading to a waste of 8 bytes (33%)`. It also reports pointer ordering, which affects how much of a value the garbage collector scans. Measured: `struct{ n int; p *int }` gives `has 16 leading bytes of pointer data but optimal value is 8`. That makes it noisy. Enable it for hot data types, not for the whole codebase.
- The starter test gives two golangci-lint warnings: QF1003 (`could use tagged switch on test.name`) and `var withSubmit is unused`. Both are starter code, not findings.

## 5.7 Empty Struct

Quiz:

1. Why does the empty anonymous struct have two pairs of braces, `struct{}{}`? `struct{}` is the type (empty struct) and `{}` is the value (empty struct literal). It is not a syntax error.

Notes:

- `struct{}{}` follows the general form `T{}` for a composite literal, with `T = struct{}`. The same pattern as `[]int{}` or `map[string]int{}`. Measured: `%v` prints `{}` and `%T` prints `struct {}`.
- An empty struct holds no information, so its size is 0. Measured: `unsafe.Sizeof(struct{}{})` is `0`. Lesson 5.8 covers the memory side.
- The two common uses are a set, `map[string]struct{}`, where only the key matters, and a signal channel, `chan struct{}`, where only the event matters. Measured: `seen["dev-1"] = struct{}{}` followed by `_, ok := seen["dev-1"]` gives `true`, and `close(done)` on a `chan struct{}` unblocked `<-done`. In a pipeline, `done chan struct{}` (or `ctx.Done()`, which returns the receive-only `<-chan struct{}`) tells workers to stop. A set of seen device IDs or message IDs, used to deduplicate, is `map[string]struct{}`.
- A zero-size field as the last field of a struct is not free. Go pads it so that a pointer to it cannot point past the end of the struct's memory. Measured: `struct{ n int64; _ struct{} }` is 16 bytes, but with the empty field first it is 8. The new `fieldalignment` setup reports it: `tail has size 16 but the optimal size is 8 leading to a waste of 8 bytes (50%)`.

## 5.8 Empty Struct Memory

Quiz:

1. Which is ordered from least to most memory usage? `struct{}`, `bool`, `uint16`, `int64`. Measured with `unsafe.Sizeof`: `0 1 2 8`.

Notes:

- Zero-size values need no memory, so the runtime does not allocate them. Measured: `new(struct{})` twice gave the same address, `0x5be1a0`, and `make([]struct{}, 1_000_000_000)` made 0 allocations (`testing.AllocsPerRun`). The spec does not promise that two zero-size variables share an address or that they differ, so never compare such pointers.
- A set as `map[K]struct{}` saves no memory over `map[K]bool` in Go 1.27. Measured with one million keys, each map in its own process: `map[string]struct{}` used 55,843,424 bytes and `map[string]bool` used 55,887,376. `map[int64]struct{}` and `map[int64]bool` used 37,751,072 and 37,761,712. A likely reason (reasoned, not read from the runtime source): a key and value pair is laid out like a struct, and a trailing zero-size field is padded (see 5.7). Measured: `struct{ k string; v struct{} }` and `struct{ k string; v bool }` are both 24 bytes. `struct{}` is still the better choice, because it shows that the value means nothing and it rules out a stray `false` entry.
- A `chan struct{}` carries no data, only the event. `close` on it reaches every receiver at once, which is how a broadcast stop signal works.

## 5.9 Update Users

- The solution sets the embedded struct's fields directly in the literal: `User{Name: name, Type: membershipType, MessageCharLimit: messageCharLimit}`. This is the Go 1.27 promoted-field form from 5.4. The older form, `Membership: Membership{Type: ..., MessageCharLimit: ...}`, is kept in a comment next to it for reference. Measured: with `-gcflags=-lang=go1.26` the build fails with `use of promoted field Membership.Type in struct literal of type User requires go1.27 or later (-lang was set to go1.26; check go.mod)`. A library whose `go.mod` says an older version must use the older form.
- Embedding `Membership` promotes `Type` and `MessageCharLimit`, so `user.Type` works. Both fields are exported, so they also appear at the top level when `User` is marshaled to JSON (see 5.4).
- `User` is 40 bytes on amd64 (`Membership` 24, `Name` 16) with no padding. The home golangci-lint config with `fieldalignment` reports nothing.
- An unknown membership type gets the standard limit, which is what the spec asks for. In production, a typed constant (`type membershipType string` with `const premium membershipType = "premium"`) and a `switch` with a `default` that returns an error make a typo visible instead of silently downgrading the user.

## 5.10 Send Message

- "Within the limit" includes the limit, so the check is `messageLength > u.MessageCharLimit` to reject. Measured: a 100-byte message for a standard user returns the message and `true`, and 101 bytes returns `false`.
- The method has a value receiver. It only reads `User`, so a copy is fine (`User` is 40 bytes). The `(string, bool)` result is the comma-ok form, like a map lookup. Production code returns an `error` that says why the message was rejected (see 5.2).
- `len` counts bytes, not characters, so the course's test enforces a byte limit. Measured: 60 Greek letters (`strings.Repeat("γ", 60)`) are 120 bytes, and a standard user's 100 "character" limit rejects them. `utf8.RuneCountInString` gives `60`. Decide which unit the limit is in. For a text limit, count runes. For a buffer, a CAN payload or an MQTT packet size, count bytes.
- The caller passes the length separately from the message, so the two can disagree. Measured: a 500-byte message with `messageLength` 1 is accepted. Compute the length inside the method from `message`, and do not take it as a parameter.
- The starter's `newUser` treats any type other than `"premium"` as standard, including `"Premium"`. Measured: `newUser("x", "Premium")` has type `standard` and limit `100`. It stores the corrected type, unlike the 5.9 solution, which stored the input as given.
