# Chapter 12: Packages and Modules

## 12.1 Packages

- Only `package main` with a `func main()` builds an executable. The same file under `package mailio` still compiles: `go build` exits 0, writes no binary, and `func main` is an ordinary unexported function. `go run` refuses it with `package pkg/lib is not a main package`.
- `math/rand` has been seeded randomly at startup since Go 1.20, and since Go 1.24 `rand.Seed` does nothing (`GODEBUG=randseednop=0` restores the old behavior). Older examples that call `rand.Seed(time.Now().UnixNano())` are dead code now. New code uses `math/rand/v2`, or `crypto/rand` for anything security-related such as tokens or keys.
- Production note: keep `package main` thin. Parse flags and config, build dependencies, and call into library packages. `main` cannot be imported, so code that lives there cannot be tested or reused from another binary. A repo with several binaries puts each one in `cmd/<name>/`.

## 12.2 Package Naming

Quiz:
- What would be the conventional package name of a package with the path `github.com/wagslane/parser`? Answer: `parser`.
- Given the import path `path/to/rand`, which of these package names are allowed by the Go compiler: `spam`, `random`, `rand`, `path`? Answer: any of these.

Notes:
- The import path finds the directory. The `package` clause sets the name the code uses. Measured: a directory `path/to/rand` holding `package spam` imports as `"pn/path/to/rand"` and is called as `spam.Eggs()`. Nothing at the import site shows the name `spam`, which is why the convention exists. When a name must differ, write it at the import: `spam "pn/path/to/rand"`.
- Two packages in one directory fail with `found packages a (a.go) and b (b.go) in .../mixed`. The one exception is an external test package: `package spam_test` in a `_test.go` file next to `package spam` builds and runs. Any other suffix fails, for example `package other_test` gives `found packages other (o_test.go) and spam (r.go)`.
- A repo or directory named with a dash, such as `go-parser`, cannot be the package name, because `-` is not valid in an identifier. Name the package `parser`.
- Production note: name packages by what they provide, short and lowercase, without `util`, `common` or `helpers`. Callers read the name at every call site, so avoid repeating it in exported names: `can.Frame`, not `can.CANFrame`.
