# Chapter 7: Errors

## 7.1 The Error Interface

- `customerCost, err := ...` followed by `spouseCost, err := ...` does not create a second `err`. `:=` needs at least one new name on the left, and names that already exist in the same scope are assigned, not redeclared. Measured: `&err` is the same address after both statements. In an inner scope, such as an `if` block, `:=` creates a new `err` that shadows the outer one.
- Returning `err` unchanged loses which send failed: both failures give `can't send texts over 25 characters`. In production, wrap it with context, for example `fmt.Errorf("send to spouse: %w", err)`. The lesson's test compares `Error()` strings exactly, so wrapping would fail it here.
- Partial failure: when the spouse message fails, the customer message was already sent and paid for, but the function returns `0`. Returning the zero value with a non-nil error is the convention the lesson asks for, and it hides the cost already spent. A billing or publish path, such as two MQTT publishes to AWS IoT, has to decide this on purpose: return the partial result with the error and document it (as `io.Writer.Write` does with `n`), or make the operation retryable and idempotent.
- The test compares error strings because two errors made by separate calls are never equal. Measured: `fmt.Errorf("x") == fmt.Errorf("x")` and `errors.New("x") == errors.New("x")` are both `false`, because each call returns a new pointer. Code that must recognize an error uses a sentinel variable and `errors.Is` (lesson 7.5).
- `fmt.Errorf` without `%w` returns the same type as `errors.New`. Measured with `%T`: `*errors.errorString` without `%w`, and `*fmt.wrapError` with one `%w`.

## 7.2 Formatting Strings Review

- `%.2f` rounds the exact binary value of the float, and an exact tie rounds to even. Measured: `2.675` gives `2.67`, because the stored value is `2.67499999999999982236`. `0.125` gives `0.12` and `0.375` gives `0.38`: both are exact in binary, so they are true ties and round to the even digit. `1.005` gives `1.00`.
- Money in a `float64` is the lesson's simplification. Measured: with variables, `0.1 + 0.2` is `0.30000000000000004` and `== 0.3` is `false`. The same expression on untyped constants is `true`, because constant arithmetic is exact, so a quick test with literals hides the problem. Production billing stores integer minor units (`int64` cents) or uses a decimal type, and formats only at the edge.
- `go vet` checks `Sprintf` verbs against argument types. Measured: `%d` with `1.4` gives `fmt.Sprintf format %d has arg 1.4 of wrong type float64`. golangci-lint runs the same check (`printf` in `govet`).
- `'%s'` wraps the value in quotes without escaping it. Measured: `"it's\n"` prints as `'it's` with a raw newline in the middle of the log line. `%q` gives `"it's\n"`, a Go-quoted string that keeps one log entry on one line. Use `%q` for untrusted values such as device IDs or payloads in logs.
- For logs that backend developers search, prefer structured logging with `log/slog` over one interpolated string. Measured with `slog.NewTextHandler`: `level=ERROR msg="sms not sent" cost=1.4 recipient="+1 (435) 555 0923"`. The handler quotes values that need it, and log tooling can filter by `recipient`.
