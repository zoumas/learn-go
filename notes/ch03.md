# Chapter 3: Conditionals

## 3.1 Conditionals

- The opening brace must be on the same line as the condition. This is not a style rule. The lexer inserts a semicolon at the end of a line that ends in an identifier, so `if x > 0` followed by `{` on the next line fails with `syntax error: unexpected newline, expected { after if clause`.
- `if` takes an optional init statement: `if n, err := read(); err != nil { ... }`. Variables declared there are in scope in every branch of the chain, including `else if` and `else`, and nowhere after it. Using `n` after the closing brace fails with `undefined: n`.
- Go has no ternary operator. Use an `if`/`else` that assigns, or a small function.
- The lesson uses `if`/`else` with two branches of equal weight, which is fine here. In production code, CodeReviewComments "Indent Error Flow" prefers handling the error or the rejected case first and returning early, so the normal path stays at the left margin. For example, `if len(msg) > maxLen { return ErrTooLong }`, then send.

## 3.2 The Initial Statement of an If Block

Quiz:

1. Why would you use the 'initial' section of an `if` statement? To keep the code concise and the scope limited.
2. Which is valid Go syntax? `if x := 5; x > 3 {`. The form with parentheses, `if (x := 5; x > 3) {`, is not.

Notes:

- Parentheses around a plain condition compile: `if (x > 0) {` is valid, and `gofmt` rewrites it to `if x > 0 {`. Parentheses around the init statement and condition together do not compile: `syntax error: unexpected :=, expected )`. The parser reads the parentheses as an expression, and `:=` is a statement.
- The init statement is any simple statement, not only a declaration. Measured: `if x++; x > 1` and `if fmt.Println("call init"); x > 1` both compile and run. A declaration with `:=` is the only common use.
- The common production form is `if err := f(); err != nil { return fmt.Errorf("...: %w", err) }` for a call that returns only an error. When the call also returns a value that is needed after the `if`, declare it outside: `v, err := f()`, then `if err != nil`. The value is out of scope after the `if` closes (see 3.1).
